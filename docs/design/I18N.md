# i18n design

## Scope

- UI only.
- Locales: `en` (default, fallback) and `vi`.

## Structure

```text
host/src/i18n/
├── index.ts            # i18next setup, supported locales, detection, fallback
└── locales/
    ├── en/common.json  # shell: header, home, vault pages, generic errors
    └── vi/common.json
tools/<slug>/ui/src/i18n/
├── en.ts               # tool strings, added to the shared i18next by the tool's remote
└── vi.ts
```

- One namespace per tool, named after its slug, loaded with the tool's UI.
- Keys are dotted and semantic, e.g. `home.title`, `errors.NOT_FOUND` in the shell, `errors.<CODE>` inside a tool namespace.
- Vault names and descriptions live in `host/catalog.config.json`, tool names and descriptions in `tools/<slug>/manifest.json`, both in every locale.

## Locale selection

1. Saved choice in `localStorage` (`goblin.locale`).
2. Otherwise the first supported language in `navigator.languages`.
3. Otherwise `en`.

`<html lang>` follows the active locale.

## Adding a locale

1. Add the code to the supported list in `host/src/i18n/index.ts`.
2. Add `locales/<code>/common.json`, `<code>.ts` for every tool, and the locale to every manifest and vault entry.
3. A test fails when any locale is missing a key that `en` has.
